# All 26 independently published Explorations: verification

Date: 24 October 2026. Scope: local application update, independent authoring sources and importable packages. This work does not publish, merge, deploy, alter production grants, release an APK or change the separate Android 1.0.14 branch.

## Delivery and architecture

All 26 registered Explorations have their own complete geometry/artwork, model, lesson state, controls and local assets. The 25 new topics use `worker-rich-v1`; Castle retains the compatible `worker-3d-v1` proof and now also owns its original vector fallback. Shared generic serializers, rendering primitives and bounded controls are not a topic dispatcher. The builder rejects runtime imports from bundled topic implementations or bundled scientific models. NASA Moon assets and Three notices are preserved. No child downloads remote dependencies or images.

The author guide is `docs/discovery-rich-packages.md`. The detailed initial plan and three topic-by-topic appendices are under `docs/plans/2026-10-24-*package*.md`. Family verification is documented in `docs/tactile-landscape-package-verification.md`, `docs/verification/2026-10-24-physical-package-conversion.md` and the space/life plan appendix. Each contains source locations, bespoke interactions, education constraints, comparison states and reproduction commands.

## Visual, mobile and educational review

Space/life: 48 matched original/package stage images, additional desktop/mobile Saturn-ring checks and five mobile drag checks. Physical: 36 matched state/viewport comparisons (72 scene images plus 18 full frames). Tactile/landscape: 40 initial comparisons plus six final Fraction/Pattern comparisons. The integrated browser also captures original and package pages at 1280×900 and 390×844 for every topic. Generic page controls, readout typography and surrounding layout intentionally differ. This is not a claim that every complete page is pixel-identical. Procedural text texture rasterization can vary by platform. Mobile means mobile web; downloaded native playback is not implemented.

Independent educational review compared the copied models and lessons with the originals. Seven state/feedback defects were corrected, including stale comparison evidence after manual changes, Fraction selected-slice bounds and split limits, and Chance's baseline/count feedback. Wrong predictions are not rewarded. Numeric/vector evidence supplements audio and visual output. Existing scientific/historical caveats remain; this migration does not claim a new external scientific peer review.

## Security and compatibility

Independent source and actual Chromium sandbox probes verified no network/storage/DOM API access, CSP-blocked external/blob imports and eval, capability rejection, bounded geometry/path/image/vector validation, cyclic/oversized output rejection and stalled-worker termination. Animated raster assets are rejected before decoding. Shape/extrude allocation estimates were checked against actual Three allocations. A late regression test covers large uncached payloads across authorization refreshes, preserving the immutable worker until its checksum actually changes.

Original IDs, bookmarks, native content and parent overrides remain. Downloaded alternatives are grouped with accessible originals, never silently substituted. Updates and rollback clear per-version child grants. Household checks remain on the server; offline and revoked sessions stop playback. No durable Discovery progress exists to migrate. Older clients cannot execute the new rich capability; the new app presents unsupported capabilities explicitly. No package is auto-approved.

Measured rich archive limits are 8 MiB compressed/12 MiB expanded to retain Solar's full local assets. Legacy limits remain unchanged. The application still has its existing household package-version quota; operators must manage retained versions rather than assume unlimited history. Browser watchdogs and bounded outputs are not a hard worker heap quota. This residual limitation is disclosed, not described as solved.

## Rollout and rollback

1. Review the source change and test evidence. Obtain separate authorization before pushing, creating a remote PR, merging or deploying.
2. Upgrade the web runtime first. Keep bundled originals and native routes unchanged.
3. Import chosen ZIPs into a non-production household, preview each, publish and approve its exact version explicitly. Do not bulk-grant existing children from original overrides.
4. Pilot selected packages with actual target devices. Catalog alternatives are labeled and grouped; existing bookmarks continue to originals.
5. Expand only after parent review. A package-only update builds one topic, uploads a new immutable version and requires new grants, without an app rebuild.
6. Roll back by republishing a known package version and obtaining fresh explicit grants. Disable a package if necessary; original routes remain available subject to their unchanged permissions. Application rollback must not pretend old clients can render rich packages.

No production migration was performed. The importable package collection and recovery source archive are deliverables, not evidence of deployment.
